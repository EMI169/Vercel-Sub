# Sub Panel — Vercel + Supabase (v1.3.0)

نسخهٔ اصلاح‌شدهٔ پروژه برای استقرار روی Vercel و اتصال به Supabase.

## تنظیم اتصال Supabase در Vercel

در Vercel وارد **Project → Settings → Environment Variables** شوید و این متغیرها را برای محیطی که Deploy می‌کنید اضافه کنید:

- `SUPABASE_URL`: آدرس پروژه، مانند `https://<project-ref>.supabase.co`
- یکی از این کلیدهای محرمانهٔ سروری:
  - `SUPABASE_SERVICE_ROLE_KEY` (پیشنهادی)
  - `SUPABASE_SERVICE_KEY` (برای سازگاری با نسخه‌های قبلی)
  - `SUPABASE_SECRET_KEY` (کلیدهای جدید Supabase)

کلید را در کد فرانت‌اند قرار ندهید و از کلید عمومی `anon` یا `publishable` به‌جای کلید سروری استفاده نکنید. بعد از تغییر Environment Variables، پروژه را دوباره Deploy کنید.

برای فعال‌کردن ثبت‌نام عمومی، متغیر اختیاری `ALLOW_REGISTER=1` را اضافه کنید. مقدار پیش‌فرض ثبت‌نام را غیرفعال نگه می‌دارد.

## راه‌اندازی دیتابیس

> **به‌روزرسانی از نسخه‌های قبلی:** بعد از Deploy نسخهٔ 1.3، فایل `schema.sql` را **یک بار دیگر** در SQL Editor اجرا کنید. این کار داده‌های فعلی را پاک نمی‌کند و فقط ستون‌های «اسم سفارشی» و «تاریخ انقضا» را اضافه می‌کند. تا این کار انجام نشود، `/api/health` پاسخ `schema_outdated` می‌دهد.

فایل `schema.sql` را در **Supabase → SQL Editor** اجرا کنید. این طرح جداول لازم برای کاربران، نشست‌ها و بخش‌ها را می‌سازد و کاربر اولیهٔ `admin` را اضافه می‌کند.

## بررسی اتصال پس از Deploy

پس از Deploy، این مسیر را در دامنهٔ Vercel باز کنید:

```text
https://<your-vercel-domain>/api/health
```

اتصال موفق:

```json
{"ok":true,"supabase":"connected"}
```

اگر تنظیمی کم باشد، پاسخ نام متغیرهای لازم را بدون نمایش مقدار کلید نشان می‌دهد. `key_rejected` معمولاً یعنی کلید اشتباه/منقضی است؛ `users_table_missing` یعنی `schema.sql` هنوز اجرا نشده است. برای بررسی کامل رفتار پنل، ورود و ساخت بخش را هم در خود سایت امتحان کنید.

## اجرای محلی و تست

Node.js 18 یا جدیدتر لازم است؛ وابستگی npm خارجی وجود ندارد.

```bash
npm test
npm run dev
```

بدون متغیر `SUPABASE_URL`، اجرای محلی از دیتابیس mock حافظه‌ای استفاده می‌کند؛ این حالت برای تست است و داده‌ها با خاموش‌شدن سرور پاک می‌شوند. این تست، دسترسی واقعی به پروژهٔ Supabase یا Deploy واقعی Vercel را جایگزین نمی‌کند.

## تغییرات نسخهٔ 1.3.0

- **اسم سفارشی برای لینک ساب:** هر ساب می‌تواند آدرسی مثل `https://<domain>/s/emi-vip` داشته باشد (۳ تا ۳۲ نویسه: حروف انگلیسی کوچک، عدد، `-` و `_`). لینک تصادفی قبلی هم همچنان کار می‌کند. عنوان ساب به‌عنوان نام پروفایل در v2rayNG نمایش داده می‌شود.
- **مدت اعتبار برای هر ساب:** دکمه‌های ۳۰ روز، ۹۰ روز، نامحدود، یا هر تعداد روز دلخواه (۱ تا ۳۶۵۰). بعد از پایان مدت، لینک دیگر کانفیگ‌ها را تحویل نمی‌دهد. اپ به‌جای کانفیگ‌ها یک مورد «⛔ اشتراک منقضی شد» می‌گیرد و مرورگر صفحهٔ «منقضی شده» نشان می‌دهد. تاریخ انقضا با هدر `Subscription-Userinfo` هم به اپ فرستاده می‌شود.
- **کوتاه‌کنندهٔ لینک:** هر چهار سرویس (is.gd، v.gd، tinyurl، spoo.me) هم‌زمان امتحان می‌شوند و اولین جواب سالم استفاده می‌شود. اگر اسم سفارشی داشته باشید، لینک کوتاه به همان اسم اشاره می‌کند.
- **رفع باگ:** دکمهٔ «ساخت لینک کوتاه» قبلاً هر بار آدرس ساب را عوض می‌کرد و لینک قبلی را از کار می‌انداخت. حالا فقط بار اول آدرس می‌سازد.
- **امنیت:**
  - رمزها با scrypt ذخیره می‌شوند. حساب‌های قدیمی با اولین ورود خودکار به‌روز می‌شوند.
  - نشست موقت admin/admin فقط برای تعیین رمز کار می‌کند.
  - روی جدول‌ها RLS فعال می‌شود تا کلید عمومی anon به آن‌ها دسترسی نداشته باشد.
- دکمه‌های «کد منبع» و «Telegram» پایین پنل.
